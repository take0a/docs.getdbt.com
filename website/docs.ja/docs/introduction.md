<Snippet path="what-is-dbt-intro" />

dbt は、データ プラットフォームに対して分析コードをコンパイルして実行し、メトリック、インサイト、ビジネス定義の単一の真実のソースでユーザーとチームが共同作業できるようにします。この単一の真実のソースと、データのテストを定義する機能を組み合わせることで、ロジックが変更されたときのエラーが削減され、問題が発生した場合に警告が表示されます。

<Lightbox src="/img/docs/cloud-overview.jpg" width="60%" title="dbt works alongside your ingestion, visualization, and other data tools, so you can transform data directly in your cloud data platform." />

アナリストがソフトウェア エンジニアのように働けるようにしたい理由の詳細については、[dbt の視点](/community/resources/viewpoint) をご覧ください。[dbt コミュニティに参加](https://www.getdbt.com/community/join-the-community) して、世界中の他のデータ実務者が dbt をどのように使用しているかを確認してください。

## dbt プロダクト

dbt を使用すると、バージョン管理、モジュール性、移植性、CI/CD、ドキュメントなどのソフトウェア エンジニアリングのベスト プラクティスに従って、データを迅速かつ共同で変換し、分析コードをデプロイできます。つまり、SQL に慣れているデータ チームのメンバーであれば誰でも、本番環境レベルのデータ パイプラインに安全に貢献できます。

### dbt Cloud

dbt Cloud は、dbt を導入するための最も高速で信頼性が高く、スケーラブルな方法を提供します。データ チームは、Web ベースのユーザー インターフェイス (UI) を通じて単一の完全に管理されたサービスを使用してデータ モデルを開発、テスト、スケジュール設定、調査することで、データ変換を最適化できます。

プランと価格については、[www.getdbt.com](https://www.getdbt.com/pricing/) でご確認いただけます。

[dbt Cloud の機能](/docs/cloud/about-cloud/dbt-cloud-features) の詳細を確認し、[dbt Cloud クイックスタート](/docs/get-started-dbt) のいずれかをお試しください。

### dbt Core 

[dbt Core](/docs/core/about-core-setup) は、データ プラクティショナーがデータを変換できるようにするオープン ソース ツールであり、dbt を手動でセットアップしてローカルで保守することを好むユーザーに適しています。コマンド ラインから [dbt Core をインストール](/docs/core/installation-overview) できます。詳細については、[dbt Core のクイックスタート](https://docs.getdbt.com/guides/codespace?step=1) を参照してください。

dbt Cloud と dbt Core の詳細については、[dbt Cloud と dbt Core の比較](https://www.getdbt.com/product/dbt-core-vs-dbt-cloud) を参照してください。

## dbt はワークフローを最適化します

- トランザクションの管理、テーブルの削除、スキーマの変更の管理により、定型的な <Term id="dml" /> および <Term id="ddl" /> の記述を回避します。必要なデータセットを返す SQL の `select` ステートメントまたは Python DataFrame のみを使用してビジネス ロジックを記述すると、dbt が <Term id="materialization" /> を処理します。
- 分析ごとに生データから開始するのではなく、後続の作業で参照できる再利用可能な、またはモジュール化されたデータ モデルを構築します。
- クエリの実行時間を大幅に短縮します。メタデータを活用して、最適化する長期実行モデルを見つけ、dbt によって簡単に構成および使用できる [増分モデル](/docs/build/incremental-models) を使用します。
- [マクロ](/docs/build/jinja-macros)、[フック](/docs/build/hooks-operations)、[パッケージ管理](/docs/build/packages)を活用して、よりドライなコードを記述します。

## dbt はより信頼性の高い分析を提供します

- ロジックが変更されたときにエラーが発生する可能性がある SQL のコピー アンド ペーストはもう不要です。代わりに、後続のモデルや分析に取り込まれる再利用可能なデータ モデルを構築します。モデルを 1 回変更すると、その変更はすべての依存関係に伝播します。
- 複雑なビジネス ロジックをすべてカプセル化した、特定のデータ モデルの標準バージョンを公開します。このモデルに基づくすべての分析には、同じビジネス ロジックが組み込まれ、再実装する必要はありません。
- ブランチ、プル リクエスト、コード レビューなどの成熟したソース管理プロセスを使用します。
- 基礎となるデータに対してデータ品質テストを迅速かつ簡単に記述します。多くの分析エラーは、データ内のエッジ ケースによって発生します。テストは、アナリストがそれらのエッジ ケースを見つけて処理するのに役立ちます。

## dbt のパワー

dbt ユーザーとして、主な焦点は、コアビジネス ロジックを反映するモデル (選択クエリ) の作成にあります。テーブルやビューを作成するための定型コードを記述したり、モデルの実行順序を定義したりする必要はありません。代わりに、dbt がこれらのモデルをウェアハウス内のオブジェクトに変換する処理を行います。

| 特徴             | 説明 |
|-----------------------|-------------|
| クエリをリレーションとして具体化するための定型コードを処理する | 作成するモデルごとに、*マテリアライゼーション*を簡単に構成できます。マテリアライゼーションは、選択クエリのビルド戦略を表します。マテリアライゼーションの背後にあるコードは、選択クエリをステートメントにラップして新しいリレーションを作成したり、既存のリレーションを更新したりする堅牢な定型 SQL です。[マテリアライゼーション](/docs/build/materializations) の詳細については、こちらをご覧ください。|
| コードコンパイラを使用する | SQL ファイルには、軽量テンプレート言語である Jinja を含めることができます。SQL で Jinja を使用すると、クエリで制御構造を使用できるようになります。たとえば、`if` ステートメントや `for` ループなどです。また、繰り返しの SQL を `macros` を通じて共有することもできます。[マクロ](/docs/build/jinja-macros) の詳細については、こちらをご覧ください。|
| モデル実行の順序を決定する | 多くの場合、データを変換するときは、段階的なアプローチで実行することが理にかなっています。dbt は、[ref 関数](/reference/dbt-jinja-functions/ref) を通じて段階的に変換を実装するメカニズムを提供します。ウェアハウス内の既存のテーブルやビューから選択するのではなく、別のモデルから選択できます。|
| dbtプロジェクトを文書化する | dbt Cloud では、dbt プロジェクトの実行時にドキュメントを自動生成できます。dbt は、dbt モデルのドキュメントの作成、バージョン管理、共有を行うメカニズムを提供します。各モデルとフィールドの説明 (プレーン テキストまたはマークダウン) を記述できます。詳細については、[ドキュメント](/docs/build/documentation) を参照してください。|
| モデルをテストする |   テストは、モデルによって生成された結果についてアサーションを行うことで、各モデルの SQL の整合性を向上させる方法を提供します。ボタンをクリックするか、[dbt Cloud IDE](/docs/cloud/dbt-cloud-ide/develop-in-the-cloud) コマンド バーを使用して、プロジェクトをビルド、テスト、実行します。モデルのテストの記述の詳細については、[テスト](/docs/build/data-tests) を参照してください。|
| パッケージを管理する | dbt にはパッケージ マネージャーが付属しており、アナリストは dbt コードのパブリック リポジトリとプライベート リポジトリの両方を使用および公開して、他のユーザーが参照できるようになります。[パッケージ管理](/docs/build/packages) の詳細については、こちらをご覧ください。 |
| シードファイルを読み込む| 多くの場合、分析では、生の値をもっと読みやすい値にマッピングしたり (たとえば、国コードを国名に変換したり)、静的なデータや頻繁に変更されないデータで強化したりする必要があります。シード ファイルと呼ばれるこれらのデータ ソースは、`project` に CSV ファイルとして保存し、`seed` コマンドを使用してデータ ウェアハウスに読み込むことができます。[Seeds](/docs/build/seeds) の詳細については、こちらをご覧ください。|
| スナップショットデータ | 多くの場合、データ ソース内のレコードは変更可能であり、時間の経過とともに変化します。履歴値を再構築する場合、分析でこれを処理するのは難しい場合があります。dbt は、[スナップショット](/docs/build/snapshots) を使用して、ある時点の生のデータをスナップショットするメカニズムを提供します。|
