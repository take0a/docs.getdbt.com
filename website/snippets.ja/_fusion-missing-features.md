
| <div style={{width:'240px'}}>Feature</div> | <div style={{width:'200px'}}>This will affect you if...</div> |

| Cloud CLI 構成 (DWH 認証情報、環境変数)            | dbt プラットフォームアカウントをお持ちで、Fusion CLI を使用してローカルで開発を行いたいのですが、profiles.yml がローカルで設定されていません。dbt init を使用すると、ガイド付きのプロファイル設定エクスペリエンスを利用できます。今後、Fusion は dbt プラットフォームで設定された DWH 接続を使用することで、設定の重複や相違を削減する予定です。 |
| [エクスポージャー](/docs/build/exposures) (["auto" + "active"](/docs/cloud-integrations/downstream-exposures) を含む) | エクスポージャー: 選択方法を使用するか、DAG オーケストレーション中にダウンストリーム エクスポージャーの更新をトリガーします。Fusion で実行されるジョブを含む、docs generate がチェックされている dbt ジョブは、引き続きエクスポージャーに関するメタデータを生成し、カタログ リネージに表示します。 |
| [persist_docs](/reference/resource-configs/persist_docs)                      | リモート データ プラットフォームのオブジェクト レベルおよび列レベルのコメントとして、dbt 永続化記述 (dbt yaml ファイルで定義) に依存します。 |
| [--store-failures](/reference/resource-configs/store_failures)                | dbt テストの --store-failures 機能を使用して、テスト クエリの結果を監査テーブルに具体化します。 |
| ["clone" command](/reference/commands/clone)                                  | 開発環境またはCI環境をセットアップするには、cloneコマンドを使用します。Fusionは、クローン作成の代替として、遅延をサポートしています。あるいは、dbt CoreでCIジョブを実行し続けることも、run-operationを使用してスキーマをクローンすることも、DWHで手動でクローンを作成することもできます。 |
| Unsupported materializations: [microbatch incremental strategy](/docs/build/incremental-microbatch), [materialized views](/docs/build/materializations#materialized-view), [dynamic tables](/reference/resource-configs/snowflake-configs#dynamic-tables), [custom materializations](/guides/create-new-materializations?step=1) | ビュー、テーブル、増分以外のマテリアライゼーションを使用してモデルを設定しています。これらのモデルをFusionで実行することはまだできませんが、標準のマテリアライゼーションを使用してモデルを実行することは可能です。 |
| [query-comment](/reference/project-configs/query-comment)                     | クエリを分析するには、dbt モデル メタデータの先頭または末尾に追加された SQL コメントに依存します。 |
| [--warn-error, --warn-error-options](/reference/global-configs/warnings)      | 警告イベント名を設定することで、すべての警告または特定の警告をエラーにアップグレードするか、特定の警告を非表示にしています。Fusion のログシステムは不完全かつ不安定であるため、特定のイベント名は変更される可能性があります。 |
| [Advanced CI ("compare changes")](https://docs.getdbt.com/docs/deploy/advanced-ci) | dbt プラットフォームでは、Advanced CI の「変更の比較」機能を使用します。  |
| ["Model governance"](/docs/mesh/govern/about-model-governance) | 契約/制約、アクセス参照の制限（グループ内のプライベート + パッケージ内の保護）、deprecation_date 警告。データ プラットフォームで強制モデル契約またはテンプレート制約（PK/FK など）が設定されているモデルがある場合、Fusion ではこれらの機能がまだサポートされていません。access: private が設定されているグループ内にモデルがある場合、Fusion では他のグループ内のモデルによるそれらのモデルへの参照がまだ制限されていません。プロジェクトがパッケージ依存関係としてインストールされている場合、Fusion では restrict-access: true が設定されているプロジェクト内のプライベート/保護モデルへの参照もまだ制限されていません。（この制限は、dbt Mesh のプロジェクト依存関係には適用されます。）`deprecation_date` が設定されているモデルがある場合、Fusion では今後または過去に廃止予定となったモデルに関する警告はまだ生成されません。Fusion のロギング システムは現在不完全で不安定です。 |
| [grants](/reference/resource-configs/grants)                                       | 権限付与設定を指定したので、これらのモデルを実行する際に、dbt は指定された受信者に指定された権限が付与されていることを確認します。Fusion はまだ権限付与をサポートしていません。 |
| Iceberg support (across adapters) and "catalogs" (new feature in dbt Core v1.10)   | モデルをIcebergテーブルとしてマテリアライズするように設定しているか、プロジェクトで「catalogs」を定義してIcebergモデルの外部書き込み場所を設定しています。Fusionではこれらのモデル設定はまだサポートされていません。 |
| [Logging system](/reference/events-logging)                                   | 特定のログメッセージ（構造化またはプレーンテキスト）に依存するスクリプト、ワークフロー、またはその他の統合機能があります。現在、Fusion のログシステムは不完全かつ不安定です。また、dbt Core のログと Fusion のログの間で完全な整合性を提供することも目標ではありません。 |
| [Model-level notifications](/docs/deploy/model-notifications)                 | ワークフローにおいて、dbt プラットフォームのモデルレベルの通知機能を活用しています。Fusion は現在、ジョブレベルの通知をサポートしています。 |
| [retry](/reference/commands/retry) | Fusion は、CLI コマンド dbt retry（失敗したジョブを障害発生時点から再実行）をまだサポートしていません。デプロイメント環境では、[状態認識オーケストレーション](https://docs.getdbt.com/docs/deploy/state-aware-about) を使用してジョブを再実行すると、Fusion は最新のデータがないモデルや、前回のビルド以降 freshness.build_after のしきい値を満たしていないモデルをスキップします。 |
| [--empty](/docs/build/empty-flag) and [--sample](https://docs.getdbt.com/docs/build/sample-flag) (new dbt Core v1.10 feature)  | --empty フラグは開発/CI での「ドライラン」に、--sample フラグはデータ制限のある実行に使用します。Fusion は引き続き使用できますが、これらのランタイムモードでは使用できません。Fusion のネイティブ SQL 理解を使用して --sample のサポートを実装する予定です。Fusion はモデルを実行せずにモデル SQL を静的に検証できるため、--empty は不要であると思われるかもしれません。また、Fusion は列スキーマのイントロスペクションに「空の」DWH オブジェクトを必要とせずにユニットテストを実行することもできます。 |
| [`state:modified.<subselector>` methods](/reference/node-selection/methods#state) | state:modified では精度が不十分なため、細分化された「サブセレクタ」に頼っています。Fusion の状態検出は、よりスマートですぐに使えるので、ぜひお試しください。 |
| [dbt-docs documentation site](https://docs.getdbt.com/docs/build/view-documentation#dbt-docs) and ["docs generate/serve" commands](https://docs.getdbt.com/reference/commands/cmd-docs)  | Fusion は、dbt Core が dbt-docs（静的 HTML サイト）経由で提供しているような、ドキュメントの生成、ホスティング、表示のためのローカルエクスペリエンスをまだサポートしていません。GA リリースまでに、このようなエクスペリエンスをサポートする予定です。ローカルドキュメントを生成してホスティングする必要がある場合は、dbt Core で dbt docs generate を実行して、引き続きカタログを生成してください。  |
| [Programmatic invocations](/reference/programmatic-invocations) | 呼び出しをトリガーし、イベント/ログにコールバックを登録するには、dbt Core の Python API を使用します。Fusion のロギングシステムは不完全かつ不安定であることにご注意ください。 |
| [Semantic Layer](/docs/use-dbt-semantic-layer/dbt-sl): development + saved_query exports | dbtプロジェクトで新しいセマンティックオブジェクト（semantic_models、metrics、saved_queries）を積極的に開発したり、既存のオブジェクトを変更したりする場合は、Fusionではなくdbt Coreを使用してください。Fusionではまだsemantic_manifest.json（MetricFlowへのインターフェース）が生成されないためです。保存済みクエリの「エクスポート」機能を使用する場合は、Fusionではまだサポートされていないため、引き続きdbt Coreでジョブを実行してください。 |
| [Custom snapshot strategy](https://docs.getdbt.com/reference/resource-configs/strategy#advanced-define-and-use-custom-snapshot-strategy) | 組み込みオプションの `timestamp` と `check` 以外のカスタムスナップショット戦略を使用します。 |
| [Linting via SQLFluff](https://docs.getdbt.com/docs/deploy/continuous-integration#to-configure-sqlfluff-linting) | 開発やCIワークフローでは、SQLFluffを使用してリンティングを行っています。FusionエンジンにはSQL理解機能が搭載されているため、最終的にはリンティングサポートをFusionに直接組み込む予定です。それまでは、dbt CoreとSQLFluffの統合を引き続きご利用いただけます。dbt Cloudは、Cloud IDE / StudioとCIジョブでまさにこれを実現します。 |
| [`{{ graph }}`](https://docs.getdbt.com/reference/dbt-jinja-functions/graph) - `raw_sql` attribute (e.g. specific models in [dbt_project_evaluator](https://hub.getdbt.com/dbt-labs/dbt_project_evaluator/latest/)) | `{{ graph }}` コンテキスト変数の raw_sql / raw_code 属性にアクセスすると、Fusion は実行時に空の値でスタブを作成します。この属性にアクセスしてもコードは失敗しませんが、異なる結果が返されます。これは、dbt_project_evaluator パッケージ内の 3 つの品質チェック（calculate_number_lines.sql、calculate_sql_complexity.sql、find_all_hard_coded_references.sql）で使用されます。Fusion が今後この情報を提供するための、よりパフォーマンスの高いメカニズムを開発する予定です。 |
